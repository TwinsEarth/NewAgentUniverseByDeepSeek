## 2. P0：需要修正的两项

### P0-1 · `gsn-core/src/plugin/` 的规模数字没有任何读法能得出

**位置**：v3.4.2 发布说明（`releases/v3.4.2.md`），合辑 `L6381`

**原文**：

> `gsn-core/src/plugin/` **16 文件 / 约 6,077 行**

**实测**（`main` @ `5f29a92e25`）：

| 读法 | 文件数 | 行数 |
|---|---|---|
| 顶层（`gsn-core/src/plugin/*.rs`） | **12** | 3,787 |
| 递归（含子目录） | **18** | **7,018** |

**两种读法都对不上 16 / 6,077。** 递归读法的行数差 941 行，顶层读法差 4 个文件、2,290 行。

**建议**：
1. 若该数字是为描述「插件层规模」，改为**实测值 + 口径**，例如：`gsn-core/src/plugin/`：顶层 12 个 `.rs` / 3,787 行；含子目录 18 个 / 7,018 行；
2. 更好的是**让它可复现**：在文档里写明统计命令，或放进 CI 关卡——
   ```sh
   find gsn-core/src/plugin -name '*.rs' | wc -l
   find gsn-core/src/plugin -name '*.rs' -exec cat {} + | wc -l
   ```
   这样数字变化时是**关卡报警**，而不是**文档静默过期**。

> **同一失效模式我们在本仓库也犯过**：一处断言写死 `assert_eq!(OFFICIALS.len(), 11, "the document lists eleven")`，而它从未打开过那份文档。修法是让断言去**测量**而不是**复述**。写死的计数不会在某天突然错，它**从写下那天就在慢慢过期**。

### P0-2 · 一处修复的提交归因不成立

**位置**：v3.4.5 发布说明（`releases/v3.4.5.md`），合辑 `L6462`

**原文**（大意）：

> 结算按中标价付款**实际已在 v2.9.1（commit `6f6b842`）修复**，git blame 确认

**实测**：

- commit `6f6b842e3a1d` **存在**，且确实是 v2.9.1 的发布提交（`feat(sandbox): v2.9.1 capability declaration gate, panic-free production, persist warnings`）；
- 该提交**确实包含** `gsn-core/src/marketplace/mod.rs`（+47/−65）；
- 但 **`price.min(budget)` 在该补丁中完全不存在**，`winner_price` 也仅作为**未改动的上下文行**出现。

**结论**：被引用的代码在 `main` 上确实存在（`gsn-core/src/marketplace/mod.rs:755-756`），**但那个提交不是它的来源**。归因不成立。

**建议**：二选一——
1. 用 `git log -S 'price.min(budget)' -- gsn-core/src/marketplace/mod.rs` 找到**真正引入该行**的提交并改引用；
2. 或删去提交号，只陈述现状（「当前实现按中标价付款，且拒绝用托管预算顶替」），**不给出处**。

**为什么这条值得修**：归因是**可被独立核对**的断言，核对不上会削弱同一文档里其它**本来正确**的断言的可信度。

## 3. P1：文档与代码不一致的两项

### P1-1 · `handle_plugin_api` 的位置

| | |
|---|---|
| 文档（L6398）指向 | `api/rest.rs` |
| 实际位置 | **`gsn-core/src/node.rs:1299`** |

v3.4.2 的插件管理路由全部在 `node.rs`：`/plugins/blacklist:1351`、`/plugins/stop:1448`、`/plugins/start:1453`、unblock `:1458-1466`、`/plugins/trust:1375`，均在 `rest_authorize` 之后。`api/rest.rs` 提到 "plugin" 仅在 `:8` 与 `:164`。

**建议**：改正路径，或把路由迁回 `api/rest.rs` 以符合文档描述（前者成本低得多）。

### P1-2 · 代码注释与实现不一致（内部问题，非文档错误）

`gsn-core/src/plugin/bus.rs:467` 的派发注释仍写「**五道检查**」，而 `validate_sender` 已实现**七道**（`:389-465`：签名 `:441-446`、nonce 重放 `:448-463`；`MAX_SEEN_NONCES=1024` 在 `:100`）。

**建议**：改注释。**这类不一致的危险在于**：下一个读代码的人会按注释以为少了两道检查，从而**重复实现已有保护**或**误判缺口**。

## 5. P3：性能章节缺基准（20 项断言）

**全文 6,695 行没有一处 QPS / TPS / P99 / daemon 吞吐基准。**

### 5.1 唯一名为「性能指标」的小节，三个数字都没有基准

**v2.1.8**（`releases/v2.1.8.md`，L1087-1090）：

| 声称 | 同一版本的「测试验证」 |
|---|---|
| 冷启动 < 1s（桌面） | 10/10 单元测试 + 跨平台编译 |
| 空闲内存 30-40 MB（桌面） | 同上 |
| 包体积 2.5-10 MB（桌面） | 同上 |

**建议**：要么补一个真实测量（哪怕是一台机器的 `time` / RSS 读数 + 环境说明），要么把这一节改名为**「设计目标」**。现在的写法读者会当成实测值。

### 5.2 两处被后续版本自己推翻

| 早期声称 | 后续更正 |
|---|---|
| v2.4.1 L2160「跨房间路由**恒为 7 跳**」 | v2.6.5 L3703 承认 `route_hops` **被硬编码为 7，忽略了真实深度** |
| v2.4.4 L2243「**LRU** 淘汰最久未访问」 | v2.6.7 L3801 承认实际是 **LFU** |

**这两处自我更正本身是诚实的**，也正因为如此，**建议在早期版本条目上加一行「见 vX.Y.Z 更正」**——否则只读 v2.4.x 的人会拿到已被推翻的结论。

### 5.3 无任何测量的断言（建议补或降级措辞）

`L1036-1038`（硬件/电费/部署成本）、`L1669-1675`（成本倍率表）、`L1756`（DHT `O(log N)`，**全文无 DHT 复杂度测试**）、`L2113`/`L2118`（`O(1)`，只验证了**相等性**、从未验证**代价**）、`L2158-2160`、`L3719`、`L4113`（「延迟更低、吞吐更高」，无数字）、`L4128`（容量曲线，测试只覆盖初始值）。

### 5.4 证据最扎实的（可作为补基准的模板）

- `L2165` —— 10,000 节点下断言扇入/边数/跳数上限；
- `L3712` —— **唯一的显式规模测量**：N 从 10k 翻倍到 20k，断言边数比值 < 2.5；
- `L5204` / `L5244` —— Linux 实机内存/CPU 上限行为（含 256/512 实测 FAIL）；
- `L2835` / `L2939-2941` —— 真机网络数字；
- `L5578` / `L5682` / `L5929` —— v3.x 端到端或隔离进程测试。
