# agent-universe v3.5.x 开发指导文档

**合并《v3.5.0 全量安全与工程审计（43 条）》与《v3.5.0 发布文档核查》**

---

## 这份文档是什么

两份彼此独立的审计被合并成一份可执行清单：项目自己的 v3.5.0 自我审计（43 条发现、七分片、含 v3.5.1/v3.5.2/v3.5.3 路线图），以及一份外部的发布文档核查（4 条文档缺陷、13 项未闭合、20 项无基准的性能声明）。

## 怎么用

按章节顺序自上而下做即可，不必关心某一行出自哪份报告。每一条都给出：位置、现状、动作、验收标准、建议版本。重叠处已合并并标注——重叠是两份报告里最强的信号。

## 一个必须先说清的前提

两份审计都**没有编译、没有运行**上游代码。因此**「必须先验证」一节（第 6 章）应当先做**：在未验证的基础上按本清单改代码，等于在不知道当前系统真实行为的情况下改它。

## 1. 两份审计的关系

| | 项目自我审计 | 外部文档核查 |
|---|---|---|
| 对象 | 代码与运行路径 | 发布说明与代码的一致性 |
| 规模 | 43 条发现（1 Critical / 1 High / 14 Medium / 27 Low） | 4 条文档缺陷 + 13 项未闭合 + 20 项无基准声明 |
| 方法 | 静态阅读 + 调用点核验 + 测试名映射 | 逐版本比对 + 声明回查代码 |
| 共同结论 | **文档声称的能力面大于生产实际运行面** | 同上 |

**项目自我审计（43 条）**：对象是**代码与运行路径**。方法为纯静态阅读 + 逐调用点核验 + 测试名到生产路径的映射；每条结论带文件与行号，并区分 confirmed（代码文本可直接复核）与 unverified（需运行期观测）。覆盖 A–G 七个分片：账本结算、共识身份、插件、沙箱、REST/MCP 与数值、节点接线、非 Rust 面与文档。

**外部文档核查**：对象是**发布说明与代码的一致性**。方法为逐版本比对 92 个发布说明文件、抽取全部量化声明并分类、把 20 条具名声明回查真实代码。结论：92/92 逐字一致，19/20 具名声明逐字落实——**文档的可核实性很高**——但有 4 条具体缺陷、13 项未闭合、20 项性能声明无测量。

**两者在哪里重合**：自我审计的 **F-4（High，聚合）** 说「大量库面模块在生产路径零构造，文档高估」；外部核查的 **文档缺陷** 说「某个规模数字没有任何读法能得出」「某个提交归因不成立」。**这是同一个失效模式的两个分辨率**：文档声称的能力面大于生产实际运行面。两份独立报告在此互相印证，因此这一类应被视为**已确认**，而不是待商榷。

**两者各自看不到什么**：自我审计未逐条核对发布说明里的数字与归因（它关注代码）；外部核查未做安全审计（它关注声明）。因此本清单的**安全项全部来自自我审计**，**文档项全部来自外部核查**，两者不可互相替代。

## 7. 不得回退的基线

以下八项经代码文本核实且具备真实生产调用点，是后续补丁**不得回退**的基线：

1. **资金守恒与精确整数**：Money(i64) 透明序列化；结算全量重扫后精确相等（无 epsilon、无 f64）；托管/质押/结算三条路径全部封死铸币；金额入口拒绝 JSON 浮点。
2. **证据闸门 fail-closed 与重启完整性**：需证据的任务必须存在可信信封才放行；verification_policy、winner_price、结果信封、信誉与质押均持久化并在重启后存活；关闭再打开的回归测试钉住「闸门不放宽」。
3. **独立审计有真实调用点**：independent_audit 被 REST、MCP 与结算前重放实际调用，且按重放集与当前集并集比对，能抓到「自洽但未入账」的变动。
4. **服务端裁定状态与罚则**：状态变更仅经唯一转移表，终态无入边；dispute/arbitrate 要求显式操作者；罚则由服务端规则决定而非请求体。
5. **传输鉴权 fail-closed**：REST 写路由与 MCP 写/动钱工具在未配置凭据时默认拒绝；三种 MCP 传输共用同一参数校验入口，非法金额不可能通过默认值变成 0。
6. **插件通信不可冒充**：PMB 七检查在唯一 dispatch 点执行；每插件随机 HMAC、常量时间比较；进程插件 outbox 由宿主代投且无法伪造 sender；P2P 使用 Noise 与 GossipSub 签名。
