## 建议顺序

1. **B-01 是本报告唯一的 Critical，也是全清单的第一优先项。** 攻击链：n=1 时法定人数即一人 → 任意调用方生成密钥、贴任意 DID、对自己发布的任务投 Stop 票 → 证据等级升为 Verified → 通过结算闸门放款。根因是**把「已签名」误当「已授权」**。
2. 修 B-01 的形态：委员 did 必须来自**服务端状态**（已注册、Locked 质押且金额不低于门槛、信誉达标、与发布者/执行者互不相同）；**权重由服务端按质押派生，禁止由请求体带入**。
3. **必须配套一条在旧实现上必然失败的回归测试**，并把既有「自组委员会即 accepted=true」的测试改写为拒绝——否则无法证明修复真的生效。
4. B-02 与 B-05 同属「去重窗口的生命周期未定义」，建议一并处理并显式记录窗口语义。
5. B-04（权重不派生质押）是 B-01 的**同源问题**：B-01 是委员会可自组，B-04 是权重可自报。只修 B-01 而不修 B-04，则合法委员会内的权重仍不可信。
6. B-03 为零生产调用，属收敛项，可在 v3.5.3 处理。
