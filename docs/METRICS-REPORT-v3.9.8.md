# 经济体度量报告 / Economy metrics report — v3.9.8

**E-10 的交付物**。每一个数字都注明它是**派生的**、**目标的**，还是**未知的**——
这是 `metric-claims` 关卡（v3.5.9）对本文档的要求，也是一份度量报告与一份宣传材料的区别。

---

## 四个被点名的数字

| 指标 | 状态 | 来源与说明 |
|---|---|---|
| **结算量** | **派生** | `MarketMetrics::of` 从资源账本与登记表**计算**，不累积。每一次结算都走 `nau-ledger` 的托管与释放，所以「结算量」是账本上发生的事，而不是一个计数器 |
| **对账差异** | **派生，且必须为 0** | `Reconciliation` 的三态里只有 `Agreed` 不阻断；而 `Agreed` 要求链路两侧**都存在且相等**。**非 0 即失败**——本仓库的 `economy-invariants` 关卡与 `nau-ledger` 自己的守恒检查都是这一条的守卫 |
| **拒绝率** | **派生** | 每一次拒绝都带**类型化理由**（`NauError::Validation` / `Conflict` / `InsufficientBalance`），所以「拒绝率」的分母与分子都是账本与日志里的行，而不是估计 |
| **跨链限额使用率** | **恒为 0，且这是结论** | `CrossChainSupport::current()` **在任何平台上都拒绝**，因为本仓库没有哈希时间锁合约、也没有第二条链。使用率的分母存在、分子由构造决定为 0——**这不是「还没测」，而是「没有这条通道」** |

### 本文档**没有**给出的数字，以及为什么

* **Agent 经济的真实规模**——**未知**。见下面的边界。
* **吞吐、延迟、资源占用**——**未测量**。本仓库没有可复现的基准，所以任何这样的数字都会是一个**没有五要素的声明**，
  而那正是 `metric-claims` 拒绝的东西 ✓
* **任何以「预计」「将来」开头的数字**——**目标**，若出现必标注。

## 风险仪表

风险登记表有**两张互不相交的清单**（`RiskRegister`，一条测试断言它们不相交）：

### 已被缓解（四条，各有据可查）

| 风险 | 依据 |
|---|---|
| 调用方给自己定刑 | 罚没额由 `fault_slash_bps` 计算，调用方的数字只被检查合法性然后忽略（D-03）|
| 资源界被静默越过 | 每一次变更都走 `checked_*`，溢出即拒绝而绝不饱和（D-07）|
| 私钥到达沙箱 | 支付请求只有公开字段，密钥无处可放，签名由宿主完成（E-06）|
| 一次结算报告了它并没有的一致 | 「一致」要求两侧都在且相等，缺失的一侧阻断（E-04）|

### **已知且未缓解**（四条，这是应当先读的一张）

| 边界 | 为什么没有缓解 |
|---|---|
| **跨链桥被攻破** | **未缓解，且无法从本仓库内部缓解**：会被攻破的代码不在这里，而一座桥的诚实性不是它一侧的节点能验证的。**所以本节点完全拒绝跨链结算，而不是去给一个它看不见的风险设上限。** 若将来接入一座桥，这一条**留在这张表里**，直到本仓库之外的某个东西能被证明解决了它（E-08）|
| **Agent 经济的真实规模** | **记为未知而不是估计**：本工作区报告它能测量的东西，并说明它测量不了什么。一个「预计达到 X」的数字会是一个没有五要素的声明 |
| **监管不确定性** | **未缓解，且不是本仓库能解决的**：一个司法辖区允许什么在代码库之外。**登记表把它记为一条已接受的边界，而不是一个已解决的问题** |
| **节点自己的账本是唯一记录** | **已接受**：`nau-ledger` 是唯一的事实来源（E-04），这对一致性是优势，对可用性是一个单点 |

## 明确记录的边界（E-10 第三条，逐条）

1. **「Agent 经济的真实规模仍然很小」** —— 更准确地说：**这个工作区无法测量它**。
   它有一个资源市场、一个账本、一套信誉维度与一套结算词汇，
   **而它没有生产部署，所以任何规模数字都无从谈起** ✓

2. **「跨链桥风险无法完全消除」** —— 而且**从本仓库内部完全无法消除**：
   本节点因此不提供跨链结算 ✓ ——**这是拒绝，而不是「已缓解」** ✓

3. **「监管不确定性」** —— **未缓解，且不属于本仓库**：
   一个司法辖区允许什么由该辖区决定 ✓
