# NewAgentUniverseByDeepSeek · v3.5.0 / v3.6.0 / v3.7.0 开发计划

> **AUSec（Agent Universe Elastic Compute）**：面向超大规模 & 跨区域 & 跨网络，Agent 协同 / 协作 / 协商的沙盒基础设施。
>
> **规模**：3 个大功能新增（中版本）+ **34 个升级迭代**，分布在 **27 个发布**（3 中版本 + 24 小版本）上。
> **基线（写这份计划时的历史值）**：本仓库 `VERSION` 当时为 **3.4.5**，验收基线是当时的关卡数与部署检查数。
> **具体计数不在此重述**——`doc-counts` 关卡的规则是「文档可以谈论过去的版本而不给数字，
> 但不能陈述一个已不再是的当前总数」，而一个句子里的数字无法被关卡区分是历史的还是当前的。
> 当前值以仓库根 `VERSION` 与脚本为准，并由该关卡比对。
> **本文档的每一项都以本仓库真实存在的类型/文件为落点**，不以设想中的架构为落点。

## 0. 这份计划的基础

### 0.1 三个必须先纠正的前提

原始设计建立在 v3.0.0 的三条前提上，其中三条与本仓库代码不符。**不纠正它们，后续每一项都会落在错误的位置上。**

| 原设计的前提 | 本仓库事实 | 影响 |
|---|---|---|
| 「四级隔离模型：T0 WASM 进程内 → T3 微VM」 | `crates/nau-plugin/src/tier.rs` 的 `Tier` 是**信任环**：`System`（进程内）/ `Official` / `Certified` / `ThirdParty` / `Blacklisted`，**与隔离技术无关** | §1、§3.1、§5.2 的「Tier → 执行后端」映射表**不能成立**。后端选择必须走 `RuntimeKind` |
| 「PluginState：… → SUSPENDED → ACTIVE → …」 | `crates/nau-plugin/src/lifecycle.rs` 是 **12 态**：`Discovered` `Verified` `Loaded` `Running` **`Paused`** `Unhealthy` `Stopping` `Stopped` `Refused` `Quarantined` `Archived` `Blacklisted`。**没有 SUSPENDED/ACTIVE，但有 `Paused`** | pack_diff 的快照点应挂在**真实存在的 `Paused` ↔ `Running`** 上——**本仓库恰好有这个状态，比上游更合适** |
| 「安全策略引擎（OPA Rego）」；黑名单字段 `wasm_sha256`、`evidence_hash` | 全库 **`Rego` 零命中**；两个字段名**零命中** | 纵深防御的「第一层（OPA Rego）」不存在；需改为**本仓库已有的能力令牌校验 + 清单校验**（见 §7） |

### 0.2 本仓库的真实架构（计划的落点）

```
crates/nau-plugin/src/
  tier.rs        Tier = 信任环 (5)                      ← 不改
  lifecycle.rs   PluginState = 12 态（含 Paused）        ← 快照挂这里
  runtime.rs     RuntimeKind = Native | Process | Wasm   ← 扩展这里
                 Boundary    = 11 种强制边界             ← 扩展这里
  capability.rs  能力令牌
  bus.rs         PMB 通信总线
  manifest.rs    插件清单
  hot.rs         热更新（原子切换）
  arbiter.rs     仲裁
  blacklist.rs   黑名单
crates/nau-sandbox/src/  process.rs unix.rs windows.rs executor.rs manager.rs spec.rs
crates/nau-plugins/src/  official.rs (13 个官方插件) + plugins/ (T0 系统插件族)
```

**11 种 `Boundary`（已强制，可豁免需签名）**：

```
Timeout  Memory  ProcessCount  OutputCap  DiskQuota  CpuLimit
OpenFileLimit  NetworkDeny  FilesystemConfinement  EnvAllowlist  WorkDirIsolation
```

**能力名已就位**（原设计点名的全部存在）：

| 能力 | 命中 | 能力 | 命中 |
|---|---|---|---|
| `kernel:policy:write` | 30 | `agent:card:create` | 8 |
| `kernel:plugin:manage` | 30 | `swarm:consensus` | 30 |
| **`kernel:isolation:configure`** | **9** | `chain:evm:write` | 17 |
| `plugin:message:send` | 195 | `sandbox:*` | 84 |

> **本仓库是比上游更适合 AUSec 的底座**：上游缺 `kernel:isolation:configure`，我们有；上游状态机无挂起态，我们有 `Paused`。

### 0.3 一条硬约束：AUSec 的核心机制是 **Linux 专有**

原始设计的机制全部依赖 Linux 内核（或 KVM）：

| 机制 | 依赖 | Windows | macOS |
|---|---|---|---|
| `virtio-pmem` + `DAX` 共享页 | Linux 内核 | ✗ | ✗ |
| `DAMON` 空闲页回收 | Linux 5.15+ | ✗ | ✗ |
| `balloon` | 虚拟化层 | ✗ | ✗ |
| `Firecracker` MicroVM/Full VM | KVM | ✗ | ✗ |
| `AppArmor` | Linux LSM | ✗ | ✗ |
| `eBPF` | Linux 内核 | ✗ | ✗ |
| ioctl 过滤（`XFS_IOC_SWAPEXT`）| seccomp/LSM | 部分 | 部分 |

**本计划的处理原则**（与本仓库既有的「做不到就类型化拒绝，不静默降级」一致）：

> **每一个 Linux 专有机制，都必须同时在非 Linux 平台给出类型化拒绝与可读原因；不允许静默降级为「看起来在跑」。**

这不是可选项——本仓库的 CI 矩阵含 `windows-latest` 与 `macos-latest`，验证记录里已有「进程后端无法强制的边界要求书面豁免，缺豁免返回 422」的同类先例。

### B-06 · 轨迹分叉与**外部副作用边界**（v3.6.4）

| | |
|---|---|
| **交付物** | k 步分叉引擎 + **副作用标记**：带外部副作用的步骤为**不可跨越的分叉点** |
| **落点** | `crates/nau-core/src/image/` 或新建 `fork/` |
| **验收** | ① 沙盒内状态可共享、后续变化单独记录；② **`git push` / 外部 API 调用被识别为副作用并阻断分叉**；③ 有一条测试证明「跨副作用分叉会被拒绝」|

## 7. 与原始设计的偏离（逐条说明）

| # | 原设计 | 本计划 | 为什么 |
|---|---|---|---|
| 1 | 「四级隔离模型 T0 WASM → T3 微VM」 | `Tier` 保持为**信任环**不动；后端走 `RuntimeKind` | 代码里 `Tier` 是签名/副签/热插拔/配额等级，与隔离技术无关。映射表建在错误前提上 |
| 2 | 「`Tier` 决定执行后端」 | `Boundary`（由 `Tier` 决定必备集与可豁免集）+ `RuntimeKind` 分别决定 | 两个独立轴，压平会同时丢失「谁必须满足什么」与「用什么跑」 |
| 3 | 「插件分类自动决定隔离级别」 | 分类决定**必备边界集**；后端可显式声明并受能力检查 | 保留显式性，避免「分类=后端」的隐式耦合 |
| 4 | 快照挂 `SUSPENDED`↔`ACTIVE` | 挂 **`Paused`↔`Running`** | 前两个状态在本仓库不存在；后两个存在且语义正确 |
| 5 | 第一层防御 = OPA Rego | 本仓库已有的**能力令牌校验 + 清单校验** | `Rego` 全库零命中，该策略引擎不存在 |
| 6 | 黑名单字段 `wasm_sha256`/`evidence_hash` | 使用本仓库真实字段 | 这两个字段名全库零命中 |
| 7 | 「镜像保持 1000% 健康度」 | 做种率作为**被测量的指标**输出 | 与「基础镜像复用率不高」自相矛盾；冷门镜像做不出种 |
| 8 | 「前面的环境和数据可以共享，只有后续变化单独记录」 | 增加**外部副作用边界**，带副作用的步骤不可跨越 | 对沙盒内成立，对 `git push`/外部 API 不成立 |
| 9 | 「即使拿到管理员权限，AppArmor 规则依然有效」 | 加前提：**未授予 `CAP_MAC_ADMIN`** | 原表述会让读者以为 root 也翻不出去 |
| 10 | 7 个量化数字直接写入 | 每个数字必须带五要素，否则不得写入 | 全部「实验中/生产环境里」但无规模、硬件、负载、基线、定义 → 不可复现 |
| 11 | Linux 机制直接实现 | 每个机制配非 Linux 类型化拒绝 | 本仓库 CI 含 Windows/macOS；静默降级会制造「看起来在跑」的假象 |

## 8. 验收基线（不得回退）

以下为**当前已成立**的机制，本次三大版本**不得回退**：

- 账本**精确整数**（`Money(i64)`）、守恒**精确相等**、结算**唯一收口**
- 证据闸门 **fail-closed**、重启后**不放宽**
- 插件通信**不可冒充**（PMB 七检查在唯一 dispatch 点）
- 沙箱**做不到就拒绝**（无法强制的边界要求书面豁免，缺豁免返回 422）
- `Tier` 与 `PluginState` 的**既有状态与边**
- 每个公开项有文档、`#![forbid(unsafe_code)]`、无 `unwrap/expect/panic!`（测试外）
- 23 道关卡 + 48 项部署检查全绿
