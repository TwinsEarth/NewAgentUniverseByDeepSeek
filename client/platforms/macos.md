# Building the Tauri shell on macOS

> **This was never built on the authoring machine.** No macOS host was available,
> and no `cargo build`/`tauri build` was attempted for the Tauri crate at all
> (see `client/README.md` section 7). Everything below is the documented local
> procedure, not a verified transcript.

## 1. Prerequisites

* **Xcode Command Line Tools** - the linker, `clang`, and the macOS SDK. Without
  them the build fails at link time with `xcrun: error: invalid active developer
  path`, which names neither Xcode nor the fix:

  ```sh
  xcode-select --install
  xcode-select -p          # must print a path such as /Library/Developer/CommandLineTools
  clang --version
  ```

* **Rust**, built against the same SDK:

  ```sh
  rustup toolchain install 1.85.0
  rustup default 1.85.0
  ```

* **The Tauri CLI** (there is no npm project here, so use the cargo subcommand):

  ```sh
  cargo install tauri-cli --version "^2" --locked
  ```

* **Node.js 20+** only if you keep the `icons/generate.mjs` script, which uses
  `node:zlib` and nothing else.

## 2. Build

```sh
cd client/src-tauri
cargo build            # the Rust side only: fastest way to see real errors
cargo tauri build      # the bundle: .app and .dmg under target/release/bundle/
cargo tauri dev        # run it against a live daemon
```

Start a daemon first, in another terminal:

```sh
cargo build -p nau-node --bin nau-daemon
./target/debug/nau-daemon --api-port 4002 --ephemeral
```

The shell reads `NAU_DAEMON_URL` (default `http://127.0.0.1:4002`):

```sh
NAU_DAEMON_URL=http://127.0.0.1:4100 cargo tauri dev
```

Because the CSP in `tauri.conf.json` names `http://127.0.0.1:4002` and
`http://localhost:4002` in `connect-src`, pointing the shell at another port
requires editing that list too. A blocked request in the WebView shows up in
Safari's Develop menu, under your app, in the Console.

## 3. Icons

`bundle.icon` lists three PNGs that are checked in and are generated by
`icons/generate.mjs`. They are placeholders, not artwork. For a real release,
regenerate the full set - including the `.icns` that macOS bundling wants - with
the CLI, which needs the PNGs to exist first:

```sh
cargo tauri icon icons/128x128@2x.png
```

That writes `icons/icon.icns` and the other sizes. **Do not** add a reference to
`icon.icns` in `tauri.conf.json` before the file exists: upstream's
`desktop/src-tauri/tauri.conf.json:34-35` required `icons/icon.icns` and
`icons/icon.ico`, both `.gitignore`d and absent from the repository, so
`tauri build` could never succeed on either platform.

## 4. Signing and notarisation (release only)

Unsigned `.app` bundles are quarantined by Gatekeeper on another machine. To ship
one you need a Developer ID Application certificate and `notarytool` credentials;
`tauri build` reads them from the environment (`APPLE_CERTIFICATE`, `APPLE_ID`,
`APPLE_PASSWORD`, `APPLE_TEAM_ID`). Not attempted here.

## 5. What to expect instead

The **browser** client is the verified one:

```sh
node client/serve.mjs --port 8080 --daemon http://127.0.0.1:4002
node client/test/e2e.mjs       # 81 assertions, exit 0 on the authoring machine
```
